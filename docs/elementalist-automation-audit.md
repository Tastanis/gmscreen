# Elementalist automation audit and implementation plan

**Audit of the table-3d-refactor checkout at 8843a036, November 19, 2026.** This is a plan for the character builder and the 3D VTT. The test heroes were built in memory. No player sheet was regenerated.

| What was counted | Finding |
|---|---|
| Distinct Elementalist class action cards reachable across levels 1–10 and Earth, Fire, Green and Void | **56**. Forty are shared choices and sixteen are granted by the class, a selected ward or a specialization. An individual hero knows a subset. |
| Fresh builder exports with runnable v3 cards on those actions | **0 of 56**. Players still see descriptions, keywords and roll tiers. Those fields do not apply the effects to the board. |
| Previously authored class action recipes located | **10 of 56**. Two are good starting points for ordinary strikes. The other eight need a rule, a targeting correction or a host integration described below. The remaining **46** need a canonical recipe. |
| Abilities with a Persistent entry | **17**. All seventeen builder exports use wording that the current VTT maintenance detector misses. |
| Other existing automation | Four combat Essence rules already export. A saved Fire Acolyte modifier and a Burning Grounds aura also exist. Neither is an additional one of the 56 class cards. |
| Optional character-creation grants | **37** more card records from ancestries, perks and complications. They are inventoried separately because access depends on the hero's selections. |

### How coverage was checked

I enumerated catalog ability IDs, built legal drafts for each specialization at every level, substituted eligible choices, and collected the actual exported action objects by ID. The resulting IDs covered the entire 56-card class catalog. I compared the cards to the local rulebook, the authored JSON, the action tray's launch condition, runner dispatch and relevant host code. I also checked the optional grant records separately, including respite abilities without an action type. This is a source and export audit. A valid JSON block or a green harness test alone does not demonstrate that a live 3D scene implements a specific rule.

## Features that change how those 56 cards resolve

A feature can work through a native derived statistic, a resource rule, a modifier, a trigger listener or a board effect. Giving it an empty action button would miss the point. The exporter currently reduces ordinary features to display fields, so a new feature recipe also needs a path to the VTT's modifier/passive registration. Attach a fresh listener once per owning actor, including after reload or control changes.

## What to reuse and where the engine needs work

| Requirement | Existing implementation and remaining gap |
|---|---|
| One roll against several targets | The printed rules allow fewer targets and apply one roll with potentially different outcomes against each target. The v3 multi-picker permits finishing after a first pick. The runner's `runPowerRollBlock` selects one tier for the group. Keep the dice result, compute each target's tier from its own edges/banes, then run that tier’s effects against that target. This affects Bifurcated Incineration, area attacks and maintained multi-target rolls. Test two adjacent outcomes from the same dice. [Target count](../dnd/ai-reference/source/rules-v1.01b/chapters/chapter-05-classes.md#L350) · [Multi-target roll rule](../dnd/ai-reference/source/rules-v1.01b/chapters/chapter-05-classes.md#L602) |
| Choose exactly one eligible effect to remove | Existing `endCondition` handles one duration filter and a player-choice count. Add a union of eligible durations and include qualifying tracked effects. One picker should remove one instance, even when both duration types are present. Reuse it for Bountiful Decay, Test of Rain and the tree. |
| Pick relative to another target | Existing `target.near` can query a named group and preselect nearby tokens. Reuse that spatial query, then enforce the authored count, team, self-inclusion and chooser. Bind the original attacker to its event instead of showing another target picker. |
| Reuse an action or alter its delivery | `useAbility` already runs an action from another actor and can avoid charging a nested cost. `grantAction` currently posts a reminder. Resolve explicit ability roles, known IDs, action economy, controller and permitted target exceptions at invocation. Use for Subvert, Prism, Issue Order and free strikes. |
| Actor- and scene-dependent effects | `ifTarget`, `ifZone`, condition riders, aura ticks, damage-type choices and immunity bypass already support many individual steps. ## Implementation order and acceptance gates

1. **Connect canonical data to new exports.** Use the builder catalog's stable ability/feature IDs. Keep recipes on those records or in a versioned JSON lookup by the same IDs. The current action exporter already copies `a.automation` and keywords; preserve this path, and carry modifiers/passives through feature export. Give a card an explicit role such as signature, heroic or free-strike option where another action must call it. Aliases should resolve to the same canonical definition. Gate everything by actual grants. Use book base values in recipes and one modifier resolver for display and resolution. The exporter currently precomputes some bonus numbers for display, while the runner can apply feature modifiers at cast time. Test against double counting. Open a disposable hero in the real action tray and invoke Hurl from both entry points.
2. **Author simple compositions first.** Use existing v3 target, powerRoll, damage, potency, condition, forcedMovement, choice and spend capabilities. Good first fixtures are Bifurcated Incineration (multi-target roll), Viscous Fire (typed damage and movement), Ray of Agonizing Self-Reflection (tiered potency) and Unquenchable Fire (immunity bypass). Add the canonical JSON once per ID. Reuse the same components for optional grants. Keep book-specific numbers in JSON. Distinguish a printed keyword such as Fire from a selected damage type, and printed heroic cost from the amount paid during a free repeat. The distinction matters to Fire and Green Acolytes.
3. **Fix maintenance once for all seventeen abilities.** The exporter prints “Persist N essence”; `getPersistentValue` scans prose for “Persistent N” and `getPersistentRerunActionKind` infers the action from prose. Add versioned structured upkeep, timing, action cost, roll sharing, target binding and repeat/extend behavior, with the legacy reader for older sheets. Reuse the existing board's maintain/drop UI, essence deduction, markings and damage tracking. It currently keys an entry by ability, can replace stored target IDs on a rerun and clamps an over-budget gain to zero. Represent distinct maintained instances and the shared roll explicitly. Reject an ordinary selection that would produce negative income, prevent duplicate effects on one target, drop at encounter end and apply the cumulative damage threshold of 5 × Reason **in one turn**. Keep an explicit Director override distinguishable from the ordinary rule. Charge upkeep exactly once across the resource and zone systems. Test one repeatable strike, one repeatable area, one extend-only buff, a moving zone, and two instances on different targets before converting the other rows.
4. **Add event-bound selections and ordered reactions.** Build on the existing trigger bus, captured damage payload, saved groups, ability chaining and choices. Publish actor, source, target, origin/destination, tags, chosen damage type, applied amount, phase and event ID where needed. Before a roll, damage or move is committed, an eligible reaction can amend *that event*. After it resolves, reactions can observe the result. Add target-relative groups, bounded spend/Recovery choices and once-per-round/instance limits where the host lacks them. Exercise two potential attackers, multiple defenders, cancellation, repeated delivery, a lethal hit and the original movement continuing afterward.
5. **Extend shared 3D terrain, zone, form and actor services.** Existing templates, condition timers, zone ticks, token auras, movement previews and portal traversal provide starting points. The [3D terrain cost layer](../dnd/vtt/board3d/layers/terrain-zones.mjs) projects difficult-terrain cells without an allegiance check. Make cost, concealment, cover and entry effects query the actor, occupied cells, height, ownership and event time. Allow source-bound reversible geometry, holes with resolved falls, linked temporary portals, actor spawning/dismissal, reversible form overlays and observer-specific line of effect. A cell can be dangerous and passable at the same time. Test enemy versus ally, large footprints, vertical separation, expiry, repositioning, undo and scene reload. Reuse current movement review/override semantics.
6. **Finish cross-actor calls and authoritative state.** Resolve child abilities against the correct actor's known IDs with target and cost overrides scoped to that invocation. Apply this to Practical Magic, Subvert, granted free strikes, Prism and the summon. Record accepted steps so reconnecting cannot replay resolved damage, resource costs or explosions. For Muse of Fire, test the [Malice UI](../dnd/vtt/assets/js/ui/malice-changes.mjs) and [Sync V2 store](../dnd/vtt/lib/SyncV2Store.php) together: the existing floor at zero and authority checks matter even if a runner accepts a negative delta. Route the specific authorized exception through the normal GM state change. For history, magical senses and off-map consequences, present the Director with the valid target and exact rule and store the adjudicated result.
7. **Release against fresh fixtures.** For each inventory row, strict-normalize the recipe, launch it from a legally exported sheet, assert state changes and their expiry, and exercise the distinctive case in that row. Check all four specializations, the relevant levels and missing-grant cases. Test one Director client and one player client in an isolated 3D scene. Compare state after refresh and undo. Keep test fixtures and review heroes separate from current PCs. A legacy custom sheet should still run its saved JSON without automatic migration or replacement.
